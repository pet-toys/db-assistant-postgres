10.2.0
======

Removed:
- MapTimeTz no longer offers the Func<TEntity, TimeSpan?> overload. PostgreSQL
  timetz carries a UTC offset that a bare TimeSpan cannot supply, so the
  overload could never write a valid value and threw at copy time. Map timetz
  from a DateTimeOffset instead. This is source-breaking only for code that
  referenced the removed overload; no working runtime scenario is affected.

Changed:
- MapTimeStampTz from a DateTime now requires DateTimeKind.Utc. A Local or
  Unspecified value fails the copy with an InvalidOperationException that names
  the offending column and states the UTC requirement, instead of leaking an
  unqualified Npgsql error from deep in the COPY. For offset-bearing values,
  use the DateTimeOffset overload of MapTimeStampTz.
- The library no longer captures the caller's SynchronizationContext: every
  await uses ConfigureAwait(false). Callers that block on the returned task
  under a context that serializes continuations (classic ASP.NET, desktop UI)
  no longer risk a deadlock, and continuations no longer marshal back to a
  UI or request context.

10.1.0
======

Fixed:
- Identifier quoting now escapes embedded double quotes, so a table, schema, or
  column name that contains '"' is quoted correctly in the generated COPY
  command (for example, My"Table becomes "My""Table"). The previous
  already-quoted heuristic, which skipped quoting when the name started or ended
  with a quote, has been removed.
- The README usage example now calls WriteDataAsync, the actual API, instead of
  the nonexistent InsertAsync, and spells the dependency "Npgsql".

Changed:
- CreateBulkContext now validates its arguments: it throws ArgumentNullException
  for a null connection and ArgumentException for a null or whitespace table or
  schema name. WriteDataAsync throws ArgumentNullException when the entity
  collection is null, and the Map* methods throw ArgumentException for a null or
  whitespace column name.
- Mapping the same column twice now throws InvalidOperationException naming the
  duplicated column, instead of silently producing an invalid COPY command that
  failed later on the server.
